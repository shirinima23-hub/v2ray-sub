# اسکنر خودکار سرور v2ray (GitHub Actions)

هر ۶ ساعت یک‌بار، گیت‌هاب خودش سرورها را از `sources.txt` می‌گیرد، با **Xray واقعی** تست می‌کند و دو لیست اشتراک می‌سازد:

| فایل | محتوا |
|---|---|
| `output/mobile.txt` | سرورهایی که تاخیر دادند و حداقل ۲ تا از ۳ سایت (یوتیوب، اینستاگرام، تلگرام) را باز کردند. ۱۵۰ تای اول بر اساس تاخیر |
| `output/gemini.txt` | همان‌ها، ولی فقط سرورهایی که Gemini هم باز می‌کنند (کشور خروجی + API + صفحه‌ی وب) |
| `output/*_plain.txt` | همین لیست‌ها به صورت متن ساده (برای کپی دستی) |
| `output/stats.json` | آمار آخرین اجرا |

اسم هر سرور در برنامه شبیه `NL 120ms G #3` است: کشور، تاخیر (از دید سرور گیت‌هاب)، `G` یعنی جمینی هم باز می‌کند.

## راه‌اندازی (یک‌بار، حدود ۱۰ دقیقه)

1. در github.com حساب بساز و یک **ریپوی جدید و Public** بساز (مثلاً `v2ray-sub`).
   باید Public باشد وگرنه گوشی نمی‌تواند لینک را بخواند.
2. فایل‌های این پروژه را داخل ریپو بگذار:
   - `scan.py`, `sources.txt`, `README.md`
   - `output/.gitkeep`
   - `.github/workflows/scan.yml`

   اگر آپلود پوشه‌ی `.github` مشکل داشت: در گیت‌هاب **Add file ← Create new file** بزن، به جای اسم فایل بنویس
   `.github/workflows/scan.yml` (با اسلش‌ها پوشه‌ها خودکار ساخته می‌شوند) و محتوای فایل را Paste کن.
3. تب **Actions** را باز کن؛ اگر خواست، Enable کن.
4. روی **scan-servers** ← **Run workflow** بزن. اولین اجرا ۱۵ تا ۴۰ دقیقه طول می‌کشد. بعدش خودکار هر ۶ ساعت اجرا می‌شود.
5. بعد از موفق شدن، پوشه‌ی `output` پر می‌شود.

## اتصال گوشی (v2rayNG)

لینک اشتراک (به جای `USER` و `REPO` اسم خودت را بگذار):

```
https://raw.githubusercontent.com/USER/REPO/main/output/mobile.txt
```

1. v2rayNG ← منوی کناری ← **Subscription group setting** ← **+**
2. اسم دلخواه، لینک بالا را در **URL** بگذار و ذخیره کن.
3. برگرد به صفحه‌ی اصلی، منوی بالا ← **Update subscription**.
4. **Test all configs** بزن (تست از دید ایران) و روی سرور با تاخیر خوب وصل شو.
5. هر چند روز یک‌بار Update subscription بزن.

اگر `raw.githubusercontent.com` روی اینترنتت باز نمی‌شود، این آدرس را امتحان کن:
`https://cdn.jsdelivr.net/gh/USER/REPO@main/output/mobile.txt`
(کمی دیرتر به‌روز می‌شود).

## نکته‌های مهم

- تست روی سرورهای گیت‌هاب (خارج از ایران) انجام می‌شود. سروری که آن‌جا سالم است ممکن است داخل ایران فیلتر باشد؛ پس تست داخل v2rayNG را حتماً بزن.
- گیت‌هاب اگر ۶۰ روز هیچ فعالیتی در ریپو نباشد ممکن است اجرای زمان‌بندی‌شده را متوقف کند. در این صورت یک بار **Run workflow** را دستی بزن.
- تنظیمات (تعداد لینک، تعداد تست هم‌زمان، فاصله‌ی زمانی) بالای `scan.py` و داخل `scan.yml` (خط `cron`) هستند.
- لینک‌های جدید را در `sources.txt` اضافه کن (هر خط یکی).
- سرورهای رایگان عمومی امن نیستند؛ برای کارهای حساس مثل بانک استفاده نکن.

## کد چطور کار می‌کند (برای یادگیری)

1. `scan.yml` به گیت‌هاب می‌گوید: هر ۶ ساعت یک ماشین لینوکس بگیر، پایتون و Xray را نصب کن و `scan.py` را اجرا کن.
2. `scan.py` لینک‌ها را می‌گیرد و پارس می‌کند (`parse_link`)، با تست سریع TCP سرورهای مرده را حذف می‌کند، سپس برای هر سرور یک Xray موقت بالا می‌آورد و از داخلش درخواست می‌زند (`test`).
3. نتیجه مرتب می‌شود، اسم سرورها خوانا می‌شود (`rename_link`) و در `output/` نوشته می‌شود.
4. آخر workflow فایل‌های جدید را در همان ریپو commit می‌کند؛ پس لینک raw همیشه آخرین نسخه را می‌دهد.
